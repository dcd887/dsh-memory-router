给评价者：这个插件在做什么
================================================

> 对象：DSH（DeepSeek Harness）的本地插件 `@local/dsh-memory-router`
> 版本：2026-11-05，含本次四项改造
> 你大概需要 15 分钟读完，30 分钟能自己跑起来

## 一句话

它挂在模型的工具调用边界上，替模型省掉三类重复劳动：重复的工具调用、重复读进上下文的大段输出、重复注入的状态文本。

## 为什么做

DSH 的默认行为是：每次工具返回结果，模型都要重新读一遍再决定下一步。这在两种情况下是浪费：

| 情况 | 浪费 |
|---|---|
| 同一个文件/命令被调用两次 | 第二次的结果和第一次一样，但模型又要读一遍 |
| 工具返回 8000 字，模型只要 4 个字段 | 剩下 7900 字白读 |

HarnessMM（arXiv 2610.32813）把这类浪费叫「工具反馈后的无效推理回调」，给了三个机制：EDG（可执行决策图）、GDR（守卫决策复用）、CCS（认证回调替换）。这个插件是那三个机制在 DSH 上的一个可运行实现。

## 三个机制怎么落地

| 论文里的 | 在这个插件里 | 差别 |
|---|---|---|
| EDG | `edg.json` 声明式决策图：匹配工具+参数，守卫为真就跑本地动作 | 一样 |
| GDR | 工具结果返回时，插件先查决策图并自己执行（读文件、抓行、取字段） | 不能跳过模型回合——DSH 的 PostToolDecision 只有 accept/block，没有「执行下一个动作」这一支。所以省的是上下文体积，不是回合数 |
| CCS | `metrics.jsonl` 每行一条，含 charsIn/charsOut/savedTokens/turnsAvoided | 一样，但 `turnsAvoided` 只在 terminal 节点记 1，其余记 0，宁可少报 |

这个差别是刻意写进设计的：论文的 87.93% 是在 HumanEval 这种强重复链上测的，我们的负载是写作与调研，照搬那个数字会误导。

## 四个模块

| 模块 | 干什么 | 状态 |
|---|---|---|
| 去重（dedupe） | 同工具同参数，60 秒内直接复用上次的文本 | 生产验证通过 |
| 决策图（edg） | 5 个节点，命中就本地执行并替换结果 | 生产验证 2 个节点 |
| 会话延续（liveState） | 自动落盘「在处理什么、动过哪些文件」，新会话注入 | 生产验证通过 |
| 注入闸门（inject） | 内容没变不重灌，超长截断，账面行限频 | 单测通过，真实会话待验 |

## 建议你怎么评价（三个问题）

1. 这个「等价实现」站不站得住？ 论文说跳过回调，我们在 DSH 里做不到，改成「插件自己执行 + 替换输出」。这是不是同一个东西？
2. 守卫设计够不够安全？ 只允许 exitCode / fileExists / regex / minChars / jsonPath 五个算子，动作只允许 readJson / readFileSlice / grep / stat，`exec` 是未知动作直接抛错。
3. 账目可信吗？ 净收益 = 裁剪省 + 去重省 + EDG 省 − 重读赔 − 注入花 − 摘要花。「重读赔」是我自己加的科目：压缩过头会导致模型重读，那笔要算亏。

## 自己跑起来

```
cd 展示包\memory-router
node tests/offline.mjs   # 18
node tests/hooks.mjs     # 19
node tests/dedupe.mjs    # 13
node tests/edg.mjs       # 15
node tests/live.mjs      # 16
node tests/inject.mjs    # 11
node scripts/stats.mjs   # 看账本
```

测试不依赖 DSH 会话，用假 ctx 就能跑。要装进 DSH，把目录链到 profile 的 node_modules 即可。
